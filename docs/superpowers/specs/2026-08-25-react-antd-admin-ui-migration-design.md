# react-antd-admin UI、交互与功能迁移设计

## 1. 背景

源项目 `platform/react-antd-admin` 当前提交 `a2522a3` 已实现较完整的后台管理 UI、交互和通用功能，但它采用 React 19、Ant Design 6、OpenAPI 生成客户端、MSW、Go 与 PostgreSQL 的一体化架构，不符合 `product-ui/admin-temp` 的 Fake-only 母版定位。

本次迁移只把源项目的页面样式、UI 交互和通用功能带入母版。最终代码必须完全遵守母版的组件、目录、契约、路由、权限和 Fake Server 规范。

## 2. 目标

- 重做母版与源项目重叠的登录、工作台、用户、角色和审计页面，使功能深度、页面样式和交互体验以源项目为准。
- 新增源项目已有而母版缺少的忘记密码说明、登录日志、账户资料、账户设置、平台设置和关于系统页面。
- 保留母版现有的正规布局架构、标签页、全局搜索、通知、主题、偏好设置、底层组件和代码分层。
- 所有页面通过 `src/api` 请求 `/api`，由本地 Fake Server 驱动加载、写入、错误和权限状态。
- 管理员与只读身份均可离线体验完整的页面状态和权限显隐。

## 3. 不做事项

- 不迁移 Go、PostgreSQL、Docker、OpenAPI 生成层、MSW、真实 Session、CSRF、RFC 9457 或真实 API 地址。
- 不引入 Fake/Real 开关、Vite 后端代理或页面直连 Fake 数据。
- 不复制源项目的 feature-based 目录、大型页面文件或平行基础组件体系。
- 不升级 React 18、Ant Design 5、React Router 7 或母版既有技术栈。
- 不加入 SS、Agg、Chatroom、租户面等具体项目业务。
- 不要求复制源项目 DOM；要求复制用户可见的功能、样式方向和交互结果。

## 4. 总体实现原则

### 4.1 体验参考与代码所有权

源项目是产品体验规格，母版是最终代码结构的唯一标准。迁移时逐项读取源页面的可见行为，在母版中重新实现，不以复制文件后再修补的方式落地。

### 4.2 固定数据流

```text
页面 / 领域组件
  → TanStack Query useQuery / useMutation
  → src/api/<domain>
  → src/utils/request
  → /api/*
  → fake/<domain>.fake.ts
```

页面不知道数据来自 Fake。关联数据的会话内状态由 `fake/store.ts` 统一持有，对外仍由各领域 `.fake.ts` 暴露 HTTP 接口。

### 4.3 文件规模与职责

每个领域遵守以下结构：

```text
src/pages/<domain>/
├── index.tsx
├── constants.tsx
├── types.ts                 # 仅在确有页面展示类型时创建
└── components/
```

- `index.tsx` 只保留 Query/Mutation、页面状态和组件编排。
- 列定义、状态映射和 options 放 `constants.tsx`。
- Drawer、Modal、详情面板、设置分区等放 `components/`。
- 请求与响应契约放 `src/api/<domain>/types.ts`。
- 不形成源项目中 47KB 用户页、43KB 壳层式的大文件。

## 5. 基础组件与样式策略

### 5.1 Button

`BasicButton` 是唯一按钮入口。它继续采用母版当前的轻封装格式，内部直接渲染 Ant Design `Button`：

- 允许增加业务无关、语义明确的 Props，用于统一表格操作、工具栏操作和危险操作的紧凑样式。
- 自定义 Props 必须在传给 AntD 前剔除。
- 表格行操作使用紧凑文字按钮，减少内边距；危险操作使用 AntD `danger`。
- 统一覆盖 hover、focus、active、disabled 和 loading 状态。
- 不迁移源项目 `TableActionButton`，不创建第二套按钮组件。

### 5.2 Table

`BasicTable` 继续基于 Ant Design ProTable：

- 复用其刷新、密度、列设置、全屏、分页和自适应高度能力。
- 统一工具栏间距、空状态、加载状态和失败重试入口。
- 页面只提供领域列、请求参数和领域操作，不手写平行 Table 工作区。
- 列显隐和顺序使用 ProTable 已有能力；只有现有能力不能覆盖源交互时，才在 `BasicTable` 增加通用扩展。

### 5.3 主题与 CSS

- Button、Table、Card、Form、Drawer、Modal 等通用视觉优先放在 AntD Component Token 和母版基础组件。
- 页面布局使用现有 Tailwind 工具类；确有复杂状态时使用页面或组件局部样式。
- 不在页面散落全局 `.ant-*` 覆盖。
- 源项目样式需要适配母版 AntD 5 Token、明暗主题和可配置主题色。

## 6. 页面范围与交互规格

### 6.1 管理壳层

保留母版现有布局实现和能力，包括：

- 侧边、顶部、混合导航与移动端菜单。
- 标签页、刷新、关闭、最大化和拖拽。
- 全局搜索、通知、主题、语言、全屏和偏好设置。

迁入源项目的视觉与交互细节时，只改母版现有 owner：

- 统一 Header、Tabbar、侧栏、内容区和工具按钮的间距与状态。
- 已由母版实现的命令搜索、偏好设置、响应式菜单不重复建设。
- 保留母版独有的通知、权限管理与多布局能力。

### 6.2 登录与忘记密码

登录页改为源项目的聚焦式认证卡片：

- 品牌、页面说明、用户名、密码、忘记密码、登录按钮和授权访问提示集中在单卡片中。
- 顶部保留语言和主题控制。
- 登录时展示 loading，错误时在表单内展示明确错误。
- Fake-only 母版仍需提供管理员与只读账号快捷填充入口，但视觉降级为卡片底部的紧凑体验辅助，不恢复原来的大面积模板说明区。
- 忘记密码页仅说明“请联系管理员重置密码”，提供返回登录，不伪造邮件发送。

### 6.3 工作台

工作台采用源项目的问候语与统计卡片布局：

- 根据当前身份显示问候语。
- 展示用户数、角色数、登录成功数、登录失败数和审计操作数等通用指标。
- 权限不足时隐藏依赖日志权限的指标。
- 覆盖卡片骨架、无可见指标、失败重试和正常状态。
- 指标来自 `/api/dashboard/summary`，不在页面计算 Fake 数据。

### 6.4 用户管理

用户管理按源项目功能深度重做：

- 关键词和状态筛选、重置、查询与分页。
- 用户名、显示名称、邮箱、状态、创建时间和操作列。
- 支持服务端风格排序参数，由 Fake Server 执行排序。
- 使用 BasicTable 的刷新、密度、列设置和全屏工作区。
- 创建用户 Drawer。
- 编辑显示名称和状态 Modal；停用用户时展示影响提示。
- 角色分配 Drawer，区分已分配与可分配角色并即时刷新。
- 重置密码 Modal，成功后展示一次性临时密码和复制操作。
- 强制下线使用可复用危险确认组件，要求输入目标用户名确认。
- 不允许对当前登录用户执行不合理的停用或强制下线操作，并展示可读错误。
- 无管理权限时隐藏新增、编辑、分配角色、重置密码和强制下线操作。

### 6.5 角色管理

- 展示角色名称、角色标识、成员数量、权限摘要和操作。
- 创建角色、重命名角色和删除自定义角色。
- 系统内置管理员角色不可删除，并显示原因。
- 删除前展示成员数量和影响。
- 权限配置使用分组 Tree Drawer，支持展开全部、全选、清空和保存。
- 提供跳转用户管理的成员维护入口。
- 角色、用户绑定和权限绑定均保留当前预览会话内的变化。

### 6.6 权限管理

保留母版独有的权限管理页面和当前领域边界：

- 继续展示权限树与权限信息。
- 视觉、按钮和状态样式与新用户、角色页面统一。
- 不因为源项目没有独立权限页而删除该功能。

### 6.7 审计日志与登录日志

审计日志重做并新增登录日志：

- 两个页面共享通用日志表格交互，但各自保留独立领域列和筛选契约。
- 审计日志支持操作、结果、时间范围筛选，展示操作者、操作、目标、结果、IP 和发生时间。
- 登录日志支持结果、时间范围筛选，展示登录标识、结果、设备、IP、语言、时区和发生时间。
- 支持服务端风格排序、分页、刷新、密度、列设置和全屏工作区。
- 每行可打开详情 Drawer。
- 覆盖加载骨架、空数据、失败重试和无权限状态。

### 6.8 账户资料与账户设置

新增账户自助领域：

- 资料页展示头像、用户名、显示名称、邮箱、角色和创建时间，并可进入账户设置。
- 基本设置允许修改显示名称。
- 头像支持图片类型与 2MB 大小校验、上传预览和删除回退。
- API 层负责把 `File` 转成 Fake HTTP 可保存的数据，页面不感知 Fake 表示方式。
- 安全设置允许修改当前密码，并展示受影响的其他模拟会话数量。
- 登录设备列表展示设备、IP、语言、时区、创建时间和过期时间。
- 当前会话受保护；可终止单个其他会话或全部其他会话。

### 6.9 平台设置

- 支持读取和修改站点标题。
- 保存后立即更新登录页、壳层品牌与页面标题。
- 无管理权限时展示只读状态并隐藏保存操作。
- 覆盖初始骨架、保存成功、校验失败、请求失败和重试状态。

### 6.10 关于系统

- 展示 Fake Runtime 信息、母版版本和启动时间。
- 展示母版实际前端技术栈与依赖版本，不展示源项目 Go/PostgreSQL 为生产依赖。
- 展示通用技术能力与当前启用状态。
- 数据来自 `/api/system/info` 与当前包元数据构建出的前端常量。

## 7. 路由、菜单与权限

### 7.1 路由规划

- `/dashboard`：工作台。
- `/audit`：审计日志入口。
- `/audit/login`：登录日志。
- `/system/user`：用户管理。
- `/system/role`：角色管理。
- `/system/menu`：权限管理。
- `/system/settings`：平台设置。
- `/system/about`：关于系统。
- `/account/profile`：账户资料，不进入主菜单，从用户菜单进入。
- `/account/settings`：账户设置，不进入主菜单，从用户菜单或资料页进入。
- `/forgot-password`：忘记密码公开页。

### 7.2 权限规划

沿用母版现有权限格式，并增加：

- `audit:login:view`
- `system:user:force-logout`
- `system:settings:view`
- `system:settings:edit`
- `system:about:view`
- `account:view`
- `account:edit`

账户自助权限由两个 Fake 身份默认拥有。管理员拥有全部权限；只读身份只拥有查看权限。无权限操作直接隐藏，不使用 disabled 代替权限控制。

## 8. API 与 Fake 领域

### 8.1 领域文件

在现有领域基础上新增或扩展：

```text
src/api/auth/
src/api/dashboard/
src/api/audit/
src/api/login-log/
src/api/account/
src/api/system/user/
src/api/system/role/
src/api/system/menu/
src/api/system/settings/
src/api/system/info/

fake/auth.fake.ts
fake/dashboard.fake.ts
fake/audit.fake.ts
fake/login-log.fake.ts
fake/account.fake.ts
fake/system.fake.ts
fake/settings.fake.ts
fake/store.ts
```

### 8.2 统一契约

- 响应继续使用 `{ code, msg, data }`。
- 分页继续使用 `{ items, total, page, page_size }`。
- 列表请求显式携带分页、筛选、排序字段。
- 写接口返回更新后的必要数据，页面在成功后更新或失效对应 Query。
- Fake 校验返回可读 `msg`，页面使用统一错误展示方式。

### 8.3 会话内状态

`fake/store.ts` 扩展为以下关联状态的唯一 owner：

- 用户、角色、权限、用户角色、角色权限。
- 当前账户资料、头像与密码。
- 登录设备和会话。
- 站点设置。
- 用户变更产生的审计与登录日志记录。

列表筛选、排序、分页和所有写操作必须读取同一份状态，确保页面刷新后仍能看到本次预览会话内的变化。

## 9. 页面状态与响应式

每个关键页面必须覆盖：

- 初次加载骨架或合适的局部 loading。
- 正常数据。
- 空数据。
- 请求失败与重试。
- 无权限路由或操作显隐。
- Mutation pending、成功和失败。

响应式要求：

- 桌面端保持完整筛选区、表格工具栏和 Drawer 宽度。
- 窄屏筛选项换行，主次操作保持可点击间距，Drawer/Modal 使用合适宽度。
- 表格允许横向滚动，不压缩关键操作到不可用。
- 登录卡片在手机宽度下使用页面安全边距，不溢出。
- 明暗主题下不硬编码不可读的背景或文字颜色。

## 10. 测试与验证

用户已明确要求跳过 TDD，因此不执行“先写失败测试再实现”的循环。实现完成后补充以下测试：

- Fake Store 的用户、角色、账户、会话和设置状态变更测试。
- 各 Fake 路由的筛选、排序、分页和写入结果测试。
- 关键页面交互测试：用户创建/编辑/角色分配/重置密码/强制下线，角色权限配置，账户资料与会话管理，平台标题即时更新。
- 权限测试：管理员与只读身份的菜单、路由和操作显隐。
- 保留并扩展 Fake-only 架构契约测试，防止真实 API、代理或页面直连 Fake 回归。

完成前执行：

```bash
pnpm run typecheck
pnpm test -- --run
pnpm run lint
pnpm run check:circular-deps
pnpm run build:prod
```

并通过浏览器人工核对：

- 登录、忘记密码与两种模拟身份。
- 工作台、用户、角色、权限、审计、登录日志。
- 账户资料、账户设置、平台设置、关于系统。
- 明暗主题、桌面端和窄屏。
- 加载、空数据、失败、无权限和危险确认。

## 11. 实施顺序

1. 扩展基础 Button/Table 视觉入口和通用危险确认组件。
2. 扩展 Fake Store、契约和 Fake HTTP 路由。
3. 重做登录、忘记密码和工作台。
4. 重做用户、角色并统一权限页视觉。
5. 重做审计并新增登录日志。
6. 新增账户资料、账户设置、平台设置和关于系统。
7. 注册路由、菜单、权限、图标和双语文案。
8. 补行为测试与 Fake 状态测试。
9. 执行全量命令和浏览器验收。

## 12. 完成标准

- 源项目列出的通用页面功能与关键交互在母版中可离线体验。
- 重叠业务不再保留母版旧页面样式和简化交互。
- 母版现有布局架构、基础组件、API 分层、静态路由和 Fake-only 边界保持成立。
- 页面没有直接导入 Fake 数据，没有真实后端地址、代理或 Fake/Real 开关。
- 关键写操作在当前预览会话内真实改变后续页面结果。
- 管理员、只读、桌面、窄屏、明暗主题和关键异常状态均完成验证。
- 全部完成门槛命令成功，并留有新鲜输出证据。
